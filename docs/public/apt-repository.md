# Linux DEB and APT

Linux has one binary package: DEB. Direct download and APT install the same bytes. The desktop factory no longer builds a second Linux format. Full installers and the public APT channel are not published yet; the following commands describe the maintainer workflow, not a live download endpoint.

## Build and sign

On a Debian-based maintainer host, install `apt-utils`, `dpkg-dev` and `gnupg`. The signing key stays in the maintainer's private GnuPG home. It is not committed, bundled or uploaded to GitHub. Use an unlocked signing key or the maintainer's existing GPG agent.

```sh
cargo run --locked --release -p ai-phone-release-tools -- apt build dist/AI-Phone-*-linux-amd64.deb \
  --output dist/apt \
  --base-url "$APT_CHANNEL_URL" \
  --key "$APT_SIGNING_FINGERPRINT" \
  --gnupg-home "$APT_SIGNING_HOME"
```

`APT_CHANNEL_URL` is the permanent directory serving the channel's DEB assets and metadata. A flat GitHub Release asset directory or an existing static package mirror can supply it; no public application server is required. Keep the channel URI and signing key stable across package versions for normal APT upgrades. Package filenames must be unique per version. Publish complete DEBs first, then their signed metadata; retain prior package versions while clients may still reference their indexes.

The complete Linux factory automatically creates the unsigned index in `dist/apt` and includes its file identities in the unpublished candidate receipt. The existing retainer uploads those exact index files alongside the DEB. Download that candidate's metadata directory, then sign it locally without rebuilding or downloading the full installer:

```sh
cargo run --locked --release -p ai-phone-release-tools -- apt sign --output dist/apt \
  --base-url "$APT_CHANNEL_URL" \
  --key "$APT_SIGNING_FINGERPRINT" \
  --gnupg-home "$APT_SIGNING_HOME"
```

The `index` subcommand generates unsigned metadata independently. Unsigned candidate indexes are maintainer inputs, never a published APT source.

The output directory may be reused for the next version or an interrupted indexing attempt. Reindexing removes the previous signature, public-key export and source configuration before writing new indexes; sign the regenerated metadata again. Existing DEBs and unrelated files are preserved and are not listed as metadata outputs.

The output contains `Packages`, `Packages.gz`, `Release`, `InRelease`, `Release.gpg`, the public archive key and `ai-phone.sources`. Package hashes are generated by Debian's `apt-ftparchive`. DEBs are indexed without copying or repacking them. The `.sources` file embeds the exported public key and uses a flat `./` suite. See Debian's [repository generator](https://manpages.debian.org/trixie/apt-utils/apt-ftparchive.1.en.html), [source format](https://manpages.debian.org/trixie/apt/sources.list.5.en.html) and [archive authentication](https://manpages.debian.org/trixie/apt/apt-secure.8.en.html).

Publication uses the existing complete-content, source/privacy and licensing gates in `config/release-policy.json`. Building metadata does not authorize uploading an incomplete installer. Publish only the output's public metadata alongside the matching inspected DEB; never publish the GnuPG home or a test signing identity.

## User installation

After the channel is published, download its `ai-phone.sources` to `/etc/apt/sources.list.d/ai-phone.sources`, then run:

```sh
sudo apt update
sudo apt install ai-phone
```

The DEB's actual `Package` field is authoritative if the package name changes. Later versions use `sudo apt install --only-upgrade ai-phone`. A downloaded package can also be installed directly with `sudo apt install ./AI-Phone-<version>-linux-amd64.deb`. User devices, accounts, conversations and files remain in the existing application-owned user directory.

## Verification

`cargo test --locked -p ai-phone-release-tools --test apt_repository` runs the real APT client against a loopback HTTP repository. It installs and upgrades a small fixture package into an isolated root, preserves a user-file sentinel, and rejects altered package bytes and signatures. Run it as a regular user; it does not use the host's APT sources or package database. This test also runs in the required Source workflow's normal workspace tests after installing the native APT tools. Neither the tool nor its test harness uses Python. This is repository/tool verification, not physical installation acceptance of a complete AI Phone client.

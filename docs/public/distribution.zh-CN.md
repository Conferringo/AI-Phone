# 客户端、服务器、目录和升级

[English](distribution.en.md) · 2026-10-28：已实现源码打包/校验暂存；已有macOS原生客户端测试包；全新宿主部署安装器与自动更新仍待开发。

## 四个平台分别交付什么

| 平台 | 客户端目标 | 本地服务器目标 | 当前状态 |
| --- | --- | --- | --- |
| macOS | 签名/公证DMG | ARM64原生Android + Docker业务与Linux桌面 | 源码预览已验证，新增Tauri .app/DMG，连接已有部署；未做Developer ID签名/公证 |
| Windows | 签名MSI/NSIS | Windows Android Emulator + WSL2/Docker服务适配 | 原生路径、ADB边界、宿主OCR及Hyper-V资源管理待做 |
| Linux | AppImage/deb/rpm | KVM Android + Docker + systemd | 下一优先服务器目标；图像/OCR、gRPC发现、权限和无人值守启动待做 |
| Android | APK，连接用户自己的服务器 | 普通无root安卓不承诺运行整套服务器 | APK未构建；未来本机服务器属于单独实验项目 |

客户端优先采用同一轻量壳连接用户指定地址，首次只有“本机部署 / 连接服务器”。重用Web工作台；远端页面不能获得原生任意执行权限。桌面端本地部署由受限安装服务承担，Android客户端不自动下载/启动桌面服务器。客户端采用[Tauri四平台分发](https://v2.tauri.app/distribute/)；当前只验证macOS ARM64客户端，其他平台及完整宿主安装器未完成。

每个用户配置自己的服务器、模型、设备、代理与渠道；项目不默认连接开发者主机，不共享API或节点。客户端和服务端有独立版本及协议兼容范围。HTTPS/私有证书引导是远端客户端发行前置项，不能把LAN HTTP当作安全跨网络部署。

## 程序与user分离

```text
AIPhone/
  installation.json
  app/releases/0.1.0-preview.1/  # 只读目标：程序、内置Skill、模板
  current -> app/releases/...  # 当前版本
  user/
    .env                       # 数据库私有配置
    data/                      # 原有数据结构
      android/ desktop/        # 系统盘、客体主目录
      model/ channels/         # 模型版本、渠道vault/密钥
      assistant/ attachments/  # 服务私有文件、附件
      runtime-skills/ workspace/ # 实际目录以运行实现为准
```

当前 `stage` 已实现这个目录隔离，版本内的data和.env链接到user。首次安装创建current，后续只暂存，不改变正在运行的版本。现有开发目录不自动迁移，避免改坏系统盘与服务路径。PostgreSQL的Docker命名卷不在user内，**仅复制user目录不是完整备份**。现有`backup`/`restore`已覆盖数据库、Android状态、Linux根文件系统/主目录及私有文件，并通过隔离恢复和客体启动验证；应用更新中的自动停机、恢复激活与版本切换仍待实现。

内置Skill随版本更新；用户安装的Skill、记忆、知识与经验不进入源码包，不能被更新覆盖。内置Skill的停用选择也必须保留。设备型号是显示档案，不是硬件认证。资源与系统升级应独立于应用升级：不能更新前端时顺便重建手机、缩小磁盘或清空微信登录。

## 不在运行目录git pull

更新按钮应执行：检查签名版本清单 → 展示变更/兼容/空间需求 → 用户确认安装 → 等待任务检查点并停止接收新任务 → 备份数据库及私有文件、记录系统盘快照 → 下载并校验签名和哈希 → 暂存新版本 → 执行明确的数据迁移 → 启动健康检查 → 原子切换current → 保留旧版本与恢复点。

失败必须区分“程序可回退”和“数据库需恢复”；数据库有不可逆迁移时，不能只切回旧可执行文件。备份失败就不能进入应用更新。未知结果的动作/消息不能在重启时盲目重放。

`stage` 目前只实现本地包完整性校验、限制解包和版本暂存；没有发布者签名、远端版本清单、下载、迁移编排、热切换和一键恢复。**不添加一个未接通的更新按钮。** 待这些步骤完成并用备份恢复实测后，更新入口放到唯一配置中心内。

Git保留给源码开发者。GitHub Releases可承载公开发行包与签名清单，但用户数据永不上传；当前尚未公开仓库/远端发行地址，也没有任何公网发布。

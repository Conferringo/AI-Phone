产品应由应用自行部署设备和服务，用户在客户端配置资源与模型；连接已有服务器保留为可选开发/远端路径。完整安装包尚未提供。[源码和文档已公开](https://github.com/Conferringo/AI-Phone)。

| macOS ARM64 | 现有原生Android/Linux、客户端首配与原生包 | 完整干净离线资源、首轮初始化、更新激活 |
| Windows x64 | 原生客户端构建；各修订独立检查网页资源搬迁 | 设备/后端管理、路径、权限、OCR和虚拟化 |

## 已实现的目录边界

原生首配使用Tauri应用数据目录下的独立 `host`：

```text
host/
  deployment.json             首配检查点
  tools/                      当前开发安装链的受管工具
  releases/<payload-sha256>/  校验后的版本代码和运行组件
    data -> host/user/data
    .env -> host/user/.env
  user/
    .env                      私有数据库环境
    data/                     客体、账号、模型、渠道与工作文件
```

`scripts/client_host_entry.py`负责按资源摘要暂存。重试核对已有文件、依赖链接与持久目录；代码被改或目标被占用时拒绝替换，不覆盖用户状态。[预编译网页组件](runtime-bundles.md)已包含Next standalone和固定Bun；完整产品仍须补齐其他运行组件。

贡献者CLI的`scripts/release_stage.py`使用另一种版本目录：`app/releases/<version>`、首次创建的`current`和持久`user`。后续只暂存，不切换运行版本。它与原生首配的摘要目录不自动互转；现有开发目录也不自动迁移，安装客户端不会重建原有客体。

PostgreSQL使用Docker命名卷，**仅复制user不是完整备份**。备份恢复覆盖数据库、Android状态、桌面根文件系统/主目录及私有文件。恢复到空目标，保持隔离直到明确验证/激活。内置Skill属于代码版本；用户Skill、使用经验、记忆、知识、附件与停用偏好必须跨升级保留。设备扩容和系统替换独立于应用更新。

## 升级约定

目标流程：签名版本发现 → 兼容/空间检查 → 任务检查点 → 一致备份 → 签名/摘要校验 → 暂存 → 明确迁移与健康检查 → 激活或回退。备份失败不进入激活；程序回退和数据库恢复分开，不可逆迁移需兼容的数据恢复。未知设备动作与消息结果先观察，不盲目重放。

当前已有本地完整性检查、暂存和恢复工具，尚无经过认证的远端版本发现、自动运行版本切换和一键升级回退。不提供未接通的更新按钮。不能对用户运行目录直接git pull代替更新器；Git用于贡献者开发。

完整包必须包含干净Android/Linux基础、模拟器、预编译服务与匹配运行环境，并附来源、声明和适用对应源码。账号和个人设备数据不属于这些基础镜像。详见[发行要求](preview-release.md)、[当前状态](release-status.md)、[备份恢复](backup-restore.zh-CN.md)和[原始设计基线](release-contract.zh-CN.md)。

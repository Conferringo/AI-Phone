# Emulator source producer

This maintainer entry synchronizes a fixed AOSP source selection and performs one native Emulator build. It is separate from client installation. Complete-client publication remains gated on boot, dependency source and redistribution qualification.

The [source lock](source-lock.xml) contains 75 immutable project revisions derived from the official Emulator build 12560773 manifest. Linux selects 66 projects. The producer verifies each selected checkout and fourteen build-recipe blobs before invoking the pinned build entry. Its own identity is `aiphone-source-d1bfd6eb0ea9-r1`; this selection declares Emulator 35.3.8. It is not corresponding-source evidence for later Google SDK binaries.

Synchronization uses partial cloning and separates network fetch from worktree checkout. Clang expands the recipe's pinned `clang-r487747c` tree; Qt expands the native `linux-x86_64` tree with WebEngine. Both retain project-root files and the selected trees' notices. Unused compiler versions and foreign Qt variants remain unexpanded. Directory identities are checked against the locked commits before selection. All 66 projects remain selected, and both synchronization phases share the original time budget.

The receipt distinguishes initialization, fetch, input selection and checkout, with total/free disk snapshots at each boundary. The initial headroom check is an attempt threshold, not a guarantee that all sources and build outputs fit. The hosted workflow reclaims only unused preinstalled tools on its disposable runner and retains existing SDK licence records. The active disk reserve and process-ownership checks apply throughout synchronization and compilation.

The manually dispatched **Linux Emulator source build** workflow runs isolated unit contracts and real process-ownership regression first. On a disposable GitHub-hosted Linux runner, it verifies the pinned repo tag and launcher, synchronizes source and builds once. Only the fixed-field result receipt is uploaded. Binaries and private build logs are excluded. Interrupted work remains unknown and is not automatically replayed.

The source root uses the pinned upstream CLI's `Path` default, derived from its verified checkout location. That CLI accepts an explicit `--aosp` value as a string although configuration tasks require a path object. Output and distribution directories remain explicitly bound to the owned build directory.

The upstream entry runs with verbose exceptions. For a failed compilation, the receipt retains the verified producer's exit code and bounded diagnostic categories from the last 64 KiB of each build log. Traceback locations are limited to the pinned recipe files; exception messages and raw log contents are excluded from the receipt. The isolated source builder also prints the last 8 KiB of upstream output after replacing builder paths, the runner identity and credential-like lines. Full build logs and binaries are not uploaded. Missing or malformed diagnostic inputs preserve the original failure.

Run `python3 -B -m unittest -v test_aosp_emulator_producer.py test_linux_bootstrap.py` in this directory for source-contract tests. `qualify_owned_session.py` is a Linux-only regression using owned child processes. It does not access a device, network or source checkout. A real source build requires a fresh dedicated build host with sufficient resources; it is not intended for an active user-data directory.
